# SOZO Flux Node C3

这是 SOZO Flux 的 ESP32-C3 SuperMini 扩展节点固件。它通过 BLE 与 Gateway S3 连接，驱动自己的本地灯带，并执行共享灯效参数。

从 `0.2.0-alpha` 起，C3 支持通过已绑定且加密的 BLE 连接更新固件。旧版本需先通过 USB 烧录一次支持 OTA 的引导固件；之后可在 Gateway 网页的设备页选择对应 C3 和 `firmware.bin` 完成更新。传输中断、写入失败或 SHA-256 校验失败时不会启用不完整固件。

## 当前硬件

- 开发板：ESP32-C3 SuperMini（PlatformIO 目标：`esp32-c3-devkitm-1`）
- 烧录与监视串口：COM9
- 灯带数据引脚：GPIO4
- 配对按键：板载 BOOT / GPIO9
- 默认灯珠数量：60
- 可设置上限：512

## 灯珠数量怎么设置

在 Flux Hub 网页的“灯光节点”页选择这个 C3，在“灯珠数量”中填写 `1` 到 `512` 的整数并保存。

控制链路固定为：

```text
网页 → Flux Hub → BLE → C3 远程灯光节点
```

网页不会直接连接 C3。C3 是灯珠数量的唯一保存者：它把数值写入自己的 NVS，立即应用到本地灯效，再把已确认的数值回传给主控。只有网页重新读到同一个数值时，才会显示保存成功。

跟随空间场景、独立场景、断线重连、C3 重启以及清除蓝牙绑定都不会覆盖这个数值。空间场景只包含灯效、颜色、亮度和动画参数；`manualLitPixelCount` 只是一次性点亮测试，不能用来设置总灯珠数量。

`platformio.ini` 中只保留两个硬件安全参数：

- `SOZO_NODE_LED_PIN`：灯带数据引脚。
- `SOZO_NODE_MAX_LED_COUNT`：驱动可安全处理的最大灯珠数，目前为 `512`。
- `SOZO_NODE_DEFAULT_LED_COUNT`：C3 还没有保存过设置时的默认值，目前为 `60`。

如果要手动改默认值，修改 `SOZO_NODE_DEFAULT_LED_COUNT` 后重新烧录 C3；一旦网页保存过数值，C3 会优先使用已保存值。

## 模块边界

- `SozoC3Node`：处理节点协议、保存本地灯珠数量、维护场景运行时。
- `SozoBlePeripheral`：只负责 BLE GATT 连接和消息收发。
- `SOZO-Common`：S3 与 C3 共享的消息协议。
- `SozoLighting`：只负责按当前本地数量渲染灯效。

依赖始终从上层流向下层：网页不依赖 BLE，BLE 不依赖灯效，灯效不依赖网页或主控。这样增加旋钮、传感器或其他节点时，可以替换传输层而不干扰灯效层。

## 配对操作

- 首次配对：设备正常启动后，按住 BOOT 约 1.5 秒再松开。
- 清除绑定：设备正常运行时，持续按住 BOOT 8 秒，设备会清除绑定并重启。
- 上电时按住 BOOT 不会触发配对；需要先松开，再重新长按。

绑定后，节点会同时校验 SOZO 主控 NodeId 和 BLE 身份白名单。
