# SOZO Flux Gateway S3 架构入口

本工程是 SOZO Flux Hub：协调器维护权威空间场景、接收控制命令并管理节点生命周期；适配器连接网页、串口、Wi-Fi、BLE Central、NVS、板载音频和可选的本地灯光节点。

共同架构规则、术语、模块职责和接入流程以共享手册为准：

- [SOZO 代码架构手册](../SOZO-Common/docs/SOZO代码架构手册.md)
- [SOZO 统一术语](../SOZO-Common/CONTEXT.md)

S3 直连灯带不是场景权威，而是与 C3 采用相同运行时语义的本地灯光节点。本工程只能依赖 `SOZO-Common` 的核心模块，不得依赖 C3 工程，也不得保存 C3 的 GPIO、物理灯珠数或节点私有状态。

## Web 控制作用域

嵌入式网页固定使用三个一级作用域：

- **空间**：只通过 `LightingControlApplication` 修改场景或单灯带目标状态；灯效只是场景输出中的渲染算法。
- **灯光节点**：只修改选中节点自己的名称、灯珠几何、启动行为或固件。本地 S3 灯带与远程 C3 在同一节点列表中展示，灯效编辑不在此页面重复出现。
- **中枢系统**：管理 Flux Hub 的网络、节点发现、版本、诊断与维护操作。

网页可以把现有 HTTP 返回值归一化成上述视图，但不能为页面分别建立旁路状态。HTTP 请求成功只代表 Hub 接受命令；远程节点操作必须等待 `/api/nodes` 的实际回执后才能显示成功。

节点显示名称属于 Hub 管理的空间资产元数据，由 `NodeNameStore` 独立持久化；它不进入 C3 固件、BLE 协议或运行时 `NodeRegistry`。所有寻址、绑定和命令回执继续使用不可变 `nodeId`。名称修改因此由 Hub 同步确认，即使已知 C3 当前离线也不等待 BLE 回执；Hub 重启后，该 C3 首次重新注册时会恢复原名称。

网页将 Hub/C3 返回的设备快照与用户尚未保存的表单草稿分开管理。后台轮询可以刷新节点列表、在线状态和只读数据，但不得替换当前正在聚焦或含有草稿的节点编辑器；只有显式切换节点、保存成功或命令结束才能重建该编辑器。草稿按 `nodeId + field` 隔离，保存成功后才清除，失败时保留供用户重试。
